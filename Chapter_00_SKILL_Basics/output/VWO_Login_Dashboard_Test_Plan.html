1. Objective

The goal of this test plan is to ensure the quality, functionality, and reliability of the VWO Login Dashboard hosted at app.vwo.com/login.

The login dashboard is designed to handle secure user authentication for VWO’s digital experience optimization platform, covering A/B testing, personalization, and analytics products for its user base.

  • Keep an eye on guardrail metrics to stop bad changes early on.

2. Scope

Scope of Test Plan for VWO Login Dashboard:

1. Functional Testing

  • Verify the correctness and functionality of all login and authentication flows as per the requirements documentation.
  • Test various scenarios for user login, session handling, and logout.
  • Validate user authentication and authorization mechanisms for protected areas of the platform.

2. Data Validation Testing

  • Ensure that the login form correctly validates input data, rejecting invalid requests.
  • Test boundary values for input fields (email address, password) to check for any unexpected behavior.
  • Validate the accuracy of the validation messages returned to the user.

3. Error Handling Testing

  • Verify that appropriate error messages are returned for invalid login requests.
  • Check error responses for sensitive information disclosure.
  • Validate the login page’s ability to handle unexpected errors gracefully.

4. Performance Testing

  • Assess the login page’s response time under normal and peak loads to identify potential bottlenecks.
  • Measure the login throughput and scalability to handle concurrent requests.

5. Security Testing

  • Conduct security assessments to identify vulnerabilities such as SQL injection, XSS, etc.
  • Validate the login page’s compliance with secure data transmission practices (e.g., HTTPS).
  • Check for proper access controls to prevent unauthorized access to sensitive resources.

6. Integration Testing

  • Verify interactions between the login dashboard and the downstream VWO services.
  • Test data consistency across related modules.

7. Compatibility Testing

  • Test the login dashboard on different platforms, browsers, and devices to ensure cross-compatibility.

8. Documentation Review

  • Assess the clarity, completeness, and accuracy of the login dashboard documentation.
  • Verify that the documentation is in sync with the actual behavior.

9. Load Testing

  • Evaluate the login dashboard’s behavior under high concurrent user loads to ensure stability.

10. Regression Testing

  • Conduct regression testing after bug fixes or updates to ensure existing functionality remains intact.

11. Edge Case Testing

  • Test extreme and boundary scenarios to identify potential issues.

12. Concurrency Testing

  • Assess the login dashboard’s behavior when multiple users attempt to log in simultaneously.

13. Ad Hoc Testing

  • Perform exploratory testing to identify any hidden defects or usability issues.

14. Usability Testing

  • Evaluate the login dashboard’s user-friendliness and ease of use.

15. Continuous Integration and Deployment (CI/CD) Testing

  • Validate the login dashboard’s behavior within the CI/CD pipeline to ensure smooth deployments.

16. Performance Monitoring

  • Implement monitoring to track login performance in real-time.

17. Backup and Recovery Testing

  • Validate data backup and recovery procedures to ensure data integrity.

18. Internationalization Testing

  • Test the login dashboard’s behavior with different language settings.

19. Rate Limiting Testing

  • Check the login dashboard’s adherence to rate-limiting rules to prevent abuse.

20. Third-Party Integration Testing

  • Validate any third-party integrations (enterprise SSO, social login) for smooth functioning.
It’s important to note that the scope of the test plan may evolve during the testing process based on feedback, changing requirements, or discoveries during testing. The scope should be reviewed and adjusted accordingly throughout the testing phase to ensure comprehensive coverage of the VWO Login Dashboard.

3. Inclusions

Create (POST) Operations:

  • Test the login dashboard’s ability to create new user sessions using valid input data.
  • Verify that appropriate error responses are returned for invalid or missing data.
  • Validate that newly created sessions are stored correctly in the system.

Read (GET) Operations:

  • Test the login dashboard’s ability to retrieve user and session information by various criteria.
  • Verify that the dashboard returns the correct data in response to read requests.
  • Test for correct handling of non-existent or invalid session IDs.

Update (PUT) Operations:

  • Test the login dashboard’s ability to update existing user account and session data with valid input.
  • Verify that the dashboard rejects invalid update requests with appropriate error responses.
  • Validate that the account data is correctly modified in the system after updates.

Delete (DELETE) Operations:

  • Test the login dashboard’s ability to terminate sessions (logout) by providing valid session IDs.
  • Verify that the dashboard returns appropriate responses after a successful logout.
  • Validate that the terminated sessions are removed from the system.

Boundary Testing:

  • Test the login dashboard with minimum and maximum allowed values for input fields.
  • Validate the behavior of the dashboard with values close to the boundaries.

Concurrency Testing:

  • Test the login dashboard’s behavior when multiple users try to log in simultaneously.
  • Verify data consistency and handling of concurrent session modifications.

Data Validation:

  • Test the login dashboard’s response to various data validation scenarios (e.g., invalid characters, data types, mandatory fields).

Authentication and Authorization:

  • Test login flows for both authenticated and unauthenticated users.

Error Handling:

Security Testing:

Performance Testing:

Integration Testing:

Regression Testing:

Documentation Review:

Load Testing:

  • Evaluate the login dashboard’s behavior and performance under high concurrent user loads.

Compatibility Testing:

  • Test the login dashboard on different platforms, browsers, and devices.

Usability Testing:

Continuous Integration and Deployment (CI/CD) Testing:

  • Validate the login operations within the CI/CD pipeline to ensure smooth deployments.

Rate Limiting Testing:

6. Test Strategy

The first step is to create test scenarios and test cases for the various features in Scope.

While developing test cases, we’ll use a number of test design techniques.

  • Equivalence Class Partition
  • Boundary Value Analysis
  • Decision Table Testing
  • State Transition Testing
  • Use Case Testing

We also use our expertise in creating Test Cases by applying the below:

  • Error Guessing
  • Exploratory Testing
  • We prioritize the Test Cases

Step 2: Our testing procedure when we receive a request for testing:

  • First, we’ll conduct smoke testing to see if the various and important functionalities of the application are working.
  • We reject the build, if the Smoke Testing fails and will wait for the stable build before performing in depth testing of the application functionalities.
  • Once we receive a stable build, which passes Smoke Testing, we perform in depth testing using the Test Cases created.
  • Multiple Test Resources will be testing the same Application on Multiple Supported Environments simultaneously.

We then report the bugs in bug tracking tool and send dev. management the defect found on that day in a status end of the day email.

As part of the Testing, we will perform the below types of Testing:

  • Smoke Testing and Sanity Testing
  • Regression Testing and Retesting
  • Usability Testing, Functionality & UI Testing
  • We repeat Test Cycles until we get the quality product.

Step 3 – We will follow the below best practices to make our Testing better:

  • Context Driven Testing – We will be performing Testing as per the context of the given application.
  • Shift Left Testing – We will start testing from the beginning stages of the development itself, instead of waiting for the stable build.
  • Exploratory Testing – Using our expertise we will perform Exploratory Testing, apart from the normal execution of the Test cases.
  • End to End Flow Testing – We will test the end-to-end scenario which involves multiple functionalities to simulate the end user flows.
